# 麦计 · 饭点管家

把「现在几点 → 吃哪顿 → 还能吃多少 → 去哪家店 → 怎么点」一次安排明白。

## 何时使用

- 「现在这个点吃什么」「午饭/晚饭/夜宵帮我配一份」
- 「今天还剩 800 kcal，麦当劳怎么点」
- 「30 块以内，想吃辣 / 不要辣 / 要鸡肉 / 配咖啡」
- 「帮我生成一张今日饭签」

## 前置条件

需要已配置麦当劳 MCP 连接器（`mcd-mcp`，`https://mcp.mcd.cn`，Streamable HTTP，Bearer Token）。没有连接器时，先提示用户申请 Token，不要编造菜单或价格。

## 工作流

1. **定时间**
   - 调用 `now-time-info` 获取当前时间。
   - 按小时划分：05–10 早餐、10–14 午餐、14–17 下午茶、17–21 晚餐，其余夜宵。
   - 用户明确说了时段时，以用户为准。

2. **算这顿的额度**
   - 问清或沿用：每日目标（默认 1800 kcal）、今天已吃（默认 0）。
   - 剩余 = max(0, 每日目标 − 已吃)。
   - 建议额度 = 剩余 × 时段占比（早餐 25%、午餐 35%、下午茶 15%、晚餐 35%、夜宵 20%），并限制在 300–1200 kcal。
   - 用户直接给了热量目标时，直接用用户的值。

3. **选门店**
   - 调用 `query-nearby-stores`（`beType=1, searchType=2, city, keyword`）。
   - 列出 3–5 家，包含名称、距离、营业时间；让用户选，或默认最近且在营业的一家。

4. **取数与配餐**
   - `query-meals`（`storeCode, orderType=1, beType=1`）取菜单。
   - `list-nutrition-foods` 取营养表，按名称匹配（精确 → 别名 → 去杯型/规格后缀）。
   - `query-store-coupons` 取门店券。
   - 按「主餐 × 饮品 × 小食 × 甜品」组合，打分：`|热量差| × 3 + 价格 × 0.9 + 超目标惩罚 − 蛋白质 × 1.2`，口味/预算作为硬过滤。
   - 仓库在本地时，优先用确定性算法，不靠心算：

     ```bash
     node scripts/plan-cli.mjs --demo --kcal 700 --meal dinner --tastes spicy --budget 40
     ```

     也可以把 `{ items, targetKcal, tastes, mealTime, budget, coupons }` 通过 stdin 传入。

5. **核价**
   - 对每组选中的组合调用 `calculate-price`（`storeCode, orderType=1, beType=1, items`）。
   - 展示实付价，不要用菜单价相加冒充核价结果。
   - 预算内无解时，明确说“超了多少”，不要硬凑。

6. **输出**
   - 默认给 3–6 组，每组包含：搭配、总热量、蛋白质/脂肪/碳水/钠、实付价、一句推荐理由。
   - 最后给一张「今日饭签」文案：

     ```text
     【今日饭签】晚餐 · 630 kcal
     板烧鸡腿堡 + 中薯条 + 零度可乐
     蛋白质 31g · 到店自取 ¥26.5
     一句话：热量刚好落在今天的晚餐额度里。
     ```

## 规则

- 只做到店自取、单人场景；外送地址和多人拼单不在本 Skill 范围。
- 不代下单、不收集手机号/地址/订单信息；用户要下单时，引导去麦当劳官方渠道。
- 营养数据只作参考，不构成医疗或营养建议。
- 菜单、价格、营业状态以 MCP 当前返回为准；接口失败就说明失败，不要编造。
- 套餐类、周边商品不参与自动搭配。
